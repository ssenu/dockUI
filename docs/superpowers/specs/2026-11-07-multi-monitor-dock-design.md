# 모든 모니터에 독 표시, 안정성 버그 수정

작성: 2026-11-07 · 대상 버전: 0.2.9 다음 릴리스

작업 순서는 2부(버그 수정)를 먼저, 1부(모든 모니터 표시)를 나중에 한다. 2-1의 배율 수정과 2-2의 캡처 처리가 독이 여러 개일 때도 그대로 쓰이기 때문이다.

# 1부. 모든 모니터에 독 표시

## 정한 것

- 독 모드에만 적용한다. 패널 모드는 지금처럼 창 하나다.
- 트레이 메뉴에 "모든 모니터에 표시" 토글을 둔다. 기본은 켬이고 설정에 저장한다.
- 항목, 순서, 가장자리, 위치 비율, 아이콘 크기는 모든 모니터가 같다. 모니터별 설정은 없다.
- 항목을 눌러 여는 앱·크롬을 누른 모니터로 옮기지 않는다. 지금처럼 그 프로그램이 뜨던 자리에 뜬다.

## 방식

`Panel`을 모니터마다 하나씩 띄운다. 앱과 화면이 이미 메시지로만 통신하므로, 마우스 오버·확대·말풍선·끌어 놓기·DPI가 모니터별로 저절로 분리된다.

다음 두 방식은 쓰지 않는다.
- `Panel` 하나에 창 묶음 여러 개: `panel.rs`의 상태를 모두 모니터별로 다시 나눠야 하고 패널 모드를 깨뜨릴 위험이 있다.
- 모든 모니터를 덮는 큰 창 하나: 모니터별 DPI를 맞출 수 없고, 아크릴 흐림이 창 영역을 따르지 않는다(`2026-10-27-dock-blur-panel-size-design.md`의 실험 결과).

## 구성 요소

### `win/desktop.rs`

- `Monitor { handle: HMONITOR, work: PxRect, primary: bool }`
- `monitors() -> Vec<Monitor>`
- `work_area_of(handle) -> PxRect`: 모니터가 사라졌으면 주 모니터 작업 영역
- `monitor_at_cursor() -> HMONITOR`

### `ui/panel.rs`

- `OpenSpec`에 다음을 추가한다.
  - `monitor: Option<HMONITOR>`: `None`이면 주 모니터
  - `editing: bool`: 수정 모드 중에 다시 만든 독이 같은 상태로 열리게 한다
- 보조 독은 `panel_rect`로 대상 모니터의 작업 영역을 받아, 창이 처음부터 그 모니터에서 만들어지고 올바른 배율을 읽는다.
- 독 배치의 `primary_work_area()` 두 곳(`place_dock`, `move_dock`)을 `self.work_area()`로 바꾼다. 패널 모드 코드는 그대로다.
- `UiEvent::DockMoving { edge, offset }`: 끄는 중의 위치. 저장하지 않는다.
- `PanelCmd::SetDockPlacement { edge, offset, size }`: 다른 독의 위치를 맞춘다. 값이 같으면 아무것도 하지 않는다.
- `PanelCmd::Close`에서 `stop_animation()`을 먼저 부른다. 보조 독은 실행 중에 닫히므로, 애니메이션 도중 닫히면 `timeBeginPeriod`가 풀리지 않는다.

### `app.rs`

- `panel: Option<PanelHandle>`(주 패널)는 그대로 두고 `mirrors: Vec<(PanelId, PanelHandle)>`를 추가한다. 주 패널의 id는 0이다.
- `Event::Ui`는 `{ from: PanelId, event: UiEvent }`가 된다. `notify` 클로저가 id를 담아 보낸다.
- `panel_send`는 모든 독에 보낸다. 사용자 지정 테마 미리보기도 모든 독에 보낸다.
- `sync_mirrors()`: 보조 독을 모두 닫고, 필요한 모니터에 다시 연다.
- `mirror_monitors(mode, all_monitors, &monitors) -> Vec<HMONITOR>`(순수 함수): 독 모드이고 켜져 있으면 주 모니터를 뺀 나머지, 아니면 빈 목록.
- `relay_targets(from, &ids) -> Vec<PanelId>`(순수 함수): 보낸 독을 뺀 나머지.
- `dialog_owner(from)`: `from`의 유리 창. 없어졌거나 트레이에서 온 요청이면 주 패널.
- `with_modal(f)`: 대화상자·확인 창을 띄우는 동안 모든 독을 `EnableWindow(false)`로 막고 닫을 때 되돌린다. 항목 추가·수정·삭제, 테마 설정, 업데이트 확인 창에 쓴다. 지금은 소유 창 하나만 막으므로, 그대로 두면 다른 독의 클릭이 쌓였다가 창을 닫을 때 한꺼번에 실행된다.

### `config.rs`, 트레이 메뉴

- `Config.all_monitors: bool`, 기본 `true`. 필드가 없는 기존 설정도 켜진 값으로 읽는다.
- `mode_entries`의 독 수정 모드 아래에 `"    모든 모니터에 표시"`를 체크 항목으로 둔다. 독 모드일 때만 보인다.

## 데이터 흐름

| 일어난 일 | 앱의 처리 |
|---|---|
| 항목 추가·삭제·수정, 실행 중 점, 아이콘, 테마, 업데이트 단추 | 모든 독에 전달 |
| 순서 변경 | 저장 후 모든 독에 `SetTiles` (지금은 다시 보내지 않음) |
| 수정 모드 켜기·끄기 | 모든 독에 `SetEditing`. 같은 값이면 무시하므로 되풀이되지 않는다 |
| 끌어서 옮기는 중 (`DockMoving`) | 저장 없이 다른 독에만 `SetDockPlacement` |
| 놓기, 크기 변경 (`DockChanged`) | 저장 후 다른 독에 `SetDockPlacement` |
| 항목 수정·삭제·추가 요청 | 요청한 독이 있는 모니터에 창 표시 |
| 모드를 패널로 전환 | 보조 독을 먼저 닫고 주 패널에 `SetMode` |
| 모드를 독으로 전환, 토글 변경 | 주 패널에 `SetMode` 후 `sync_mirrors()` |
| 트레이 "런처 보이기", 두 번째 실행 | 커서가 있는 모니터의 독 하나만 `Show` |

`Show`를 하나만 보내는 이유: `WM_ACTIVATE`는 마지막으로 활성화된 창에만 비활성 알림을 주어 바탕으로 내린다. 모든 독을 올리면 나머지는 내려갈 기회가 없어 다른 창 위에 남는다.

독을 끌어 다른 모니터 쪽으로 넘겨도 그 독은 자기 모니터 안에 머물며 가장 가까운 가장자리에 붙는다. 다른 독은 같은 가장자리·비율로 따라온다. 해상도가 달라도 비율이 같으므로 작업 영역 안에 남는다.

## 오류·예외 처리

| 상황 | 동작 |
|---|---|
| 모니터 연결·해제, 해상도 변경 | 앱이 `WM_DISPLAYCHANGE`를 받으면 500ms 타이머로 변경을 모은 뒤 `sync_mirrors()`. `HMONITOR`가 바뀔 수 있어 다시 만든다. 주 패널은 자기 `WM_DISPLAYCHANGE`로 새 주 모니터에 다시 놓인다 |
| 작업표시줄 위치·크기 변경 | 각 독이 `WM_SETTINGCHANGE`로 자기 모니터 기준으로 다시 놓는다 |
| 모니터 배율 변경 | 각 독이 2-1의 배율 처리로 맞춘다 |
| 보조 독 생성 실패 | 로그만 남기고 그 모니터를 건너뛴다. 다음 동기화 때 다시 시도한다 |
| 그리기 장치 분실 | 독마다 기존 복구 경로와 2-1의 재시도를 탄다 |
| 이미 닫힌 독에서 온 이벤트 | 항목 id로 처리하고 대화상자는 주 패널에 띄운다 |
| 끄는 중 모니터 변경 | 끌던 독이 닫혀 끌기가 끝난다. 마지막으로 저장된 위치를 쓴다 |
| 모니터 하나 | 보조 독 목록이 비어 지금과 똑같이 동작한다 |

항목이 많아 판이 세로 모니터보다 길어지는 경우는 지금도 있는 한계이며 이번에 다루지 않는다.

# 2부. 안정성 버그 수정

## 2-1. 켜자마자 독이 안 보이는 문제

### 확인한 사실 (2026-11-07, 개발 PC, 모니터 3대·배율 혼합)

- `launcher.log`는 2026-10-26부터 전부 58줄이고, `WARN`은 네트워크 실패뿐이며 `ERROR`는 없다. 패널 창·그리기 장치·트레이 생성 실패는 로그에 없다.
- 최근 30일 Application 로그에 `YTLauncher` 충돌 이벤트가 없다.
- 부팅 40~77초 뒤에 앱이 시작한다 (부팅 이벤트와 시작 줄 비교).
- 지금 창 순서는 유리 창 z=259, 그 바로 뒤 `Progman` z=260이고, 유리 창의 소유자가 `Progman`이다.

**원인은 재현으로 확정하지 못했다.** 로그에 실패가 없으므로, 아래의 조용히 넘어가는 경로가 후보다. 다음 두 줄은 코드를 읽어 세운 가설이다.

### 후보와 수정

| 후보 | 코드 | 수정 |
|---|---|---|
| `Progman`을 못 찾아 소유자 지정이 실패하면, 결과를 버린 채 `HWND_BOTTOM`을 불러 독이 바탕화면 **뒤로** 들어갈 수 있다 | `panel.rs` `init`, `desktop.rs` `pin_to_desktop` | 결과를 로그에 남긴다. 실패하면 바탕으로 내리지 않고 2초 간격으로 최대 60초 다시 시도한다 |
| 탐색기가 다시 시작되면 소유자 `Progman`이 사라져 독 창이 없어지거나 소유자를 잃을 수 있는데, `TaskbarCreated`는 트레이만 되살린다 | `app.rs` `taskbar_created` 처리 | `TaskbarCreated`에서 유리 창이 살아 있으면 다시 소유자를 지정하고, 없어졌으면 독을 다시 연다 |
| 시작 때 저장된 패널 위치의 모니터에서 창을 만든 뒤 주 모니터로 옮기면, 중첩된 `WM_DPICHANGED`가 재진입 방어(`msg_window.rs`)에 막혀 배율이 틀린 채 남는다 | `panel.rs` `place_windows` | `place_windows` 끝에서 `scale_for(glass)`를 다시 읽어 달라졌으면 한 번 더 놓는다 |
| `Gfx::new`가 실패하면 `gfx`가 `None`인 채 다시 시도하지 않아 빈 판으로 남는다 (이 PC의 로그에는 없음) | `panel.rs` `init`, `recreate_gfx` | `gfx`가 없으면 2초 간격으로 다시 만들고, 성공하면 그린다 |

### 진단 로그

원인을 다음번에 가릴 수 있게 다음을 추가한다.
- 시작할 때: 모니터 목록·작업 영역, 배율, 소유자 지정 결과, 유리 창 사각형
- `WM_DISPLAYCHANGE`, `TaskbarCreated`를 받을 때 한 줄
- `main.rs`가 뮤텍스 확인 전에 "시작"을 남기므로, 이미 실행 중이면 "이미 실행 중"을 따로 남긴다. 지금은 사용자가 다시 실행한 것과 새로 켜진 것을 로그로 구분할 수 없다.

### 재현했을 때 확인할 것

1. 트레이 아이콘이 있는가
2. 시작 메뉴에서 다시 실행하면 독이 나타나는가
3. 그때의 `launcher.log`

독은 다른 창 뒤에 깔리는 것이 의도된 동작이므로, 켜자마자 복원된 최대화 창이 가리는 경우는 이 버그가 아니다.

## 2-2. 그 밖의 버그

모두 코드를 읽어 찾았고 재현은 하지 않았다. 구현할 때 고치기 전에 실패하는 테스트나 실제 동작으로 먼저 확인한다.

| 현상 | 위치 | 수정 |
|---|---|---|
| 웹 항목을 열면 5.5초 뒤 크롬이 최대화되며 포커스를 뺏는다. `prefer_title`이 `None`이면 제한 시간까지 기다리기 때문이다 | `chrome.rs` `focus_chrome_window` | 찾는 제목이 없으면 크롬 창이 나타나는 즉시 처리한다. 고르는 로직은 순수 함수로 뺀다 |
| 마우스 캡처를 잃으면 `press`·`drag`·`moving`이 남아 마우스 오버가 풀리지 않는다 | `panel.rs` | `WM_CAPTURECHANGED`에서 상태를 지운다. 판을 옮기던 중이면 그 위치를 저장하고, 아이콘 끌기는 취소한다 |
| "위치·크기 초기화"가 저장되지 않아 재시작하면 예전 자리로 돌아간다 | `panel.rs` `ResetGeometry` | 초기화 후 `GeometryChanged`를 보낸다 |
| 패널 모드에서 배율이 바뀌어도 다시 배치하지 않는다 | `panel.rs` `WM_DPICHANGED` | `move_window` 뒤에 `relayout_panel()`을 직접 부른다 |
| 패널 최소 높이가 모드 전환·시작 때 적용되지 않고, 자동으로 늘어난 크기도 저장되지 않는다 | `panel.rs` `SetMode`, `init`, `SetTiles` | 최소 높이 계산을 한 함수로 모아 세 곳에서 쓰고, 늘렸으면 `GeometryChanged`를 보낸다 |
| 항목 하나만 잘못돼도 설정 전체가 초기화된다 | `config.rs` `load` | 항목을 하나씩 읽어 못 읽은 것만 건너뛴다. 건너뛰면 `.bak`을 남기고 알린다 |
| 일시적인 읽기 실패에도 초기화 경로를 타, 이름 변경까지 실패하면 저장이 원본을 덮어쓸 수 있다 | `config.rs` `load` | `NotFound`가 아닌 읽기 실패는 100ms 간격으로 3번 다시 읽는다. 그래도 실패하면 기본값으로 띄우되 이번 실행은 저장하지 않는다 |
| 변환에 실패한 PNG가 남으면 항목을 수정하기 전까지 아이콘을 다시 받지 않는다 | `icons.rs`, `shell_items.rs` | 임시 파일에 쓰고 성공했을 때만 이름을 바꾼다. 실패하면 임시 파일을 지운다 |
| 쿼리에 `://`가 있으면 올바른 주소를 거부한다 (`naver.com/a?u=https://b.com`) | `items.rs` `normalize_url` | 첫 `/`·`?`·`#` 앞에 있는 `://`만 스킴 구분자로 본다 |
| 포트가 있는 사이트의 상대 아이콘 경로에서 포트를 잃는다 | `icons.rs` `resolve_url` | 호스트 대신 사용자 정보를 뺀 authority를 쓴다 |

주석·점검표 정리: `scene.rs` 머리 주석, `theme.rs` 머리 주석, `dialogs.rs` 머리 주석, `panel.rs`의 대상 없는 주석, 점검표의 "여러 줄 말풍선"·"앱을 찾을 수 없습니다" 문구를 지금 동작에 맞춘다.

# 테스트

## 단위

- `mirror_monitors`: 독·패널 모드, 켜짐·꺼짐, 모니터 1~3개 조합
- `relay_targets`: 보낸 독을 뺀 나머지
- 설정: `all_monitors` 기본값과 왕복, 항목 일부가 잘못된 파일, 읽기 실패 시 저장 안 함
- 메뉴: 독 모드에만 토글이 있고 체크가 맞음
- `desktop::monitors`: 주 모니터가 정확히 하나이고 `primary_work_area`와 일치
- 크롬 창 고르기, `normalize_url`, `resolve_url`의 새 사례
- PNG 저장 실패 시 대상 파일이 남지 않음

CI는 모니터가 보통 하나이므로 여러 모니터 동작은 수동 점검표로 확인한다.

## 수동 점검표 (`docs/manual-test-checklist.md`에 추가)

모든 모니터 표시:
- 모든 모니터에 같은 항목·위치·크기로 뜨고, 트레이에서 켜고 끌 수 있으며 재시작 후 유지된다
- 배율이 다른 모니터에서도 또렷하고, 확대와 말풍선은 마우스가 있는 독에서만 나타난다
- 한 독에서 항목을 추가하거나 순서를 바꾸면 다른 독에 바로 반영된다
- 끌어서 옮기면 다른 독이 함께 움직이고, 수정 끝내기 후 재시작해도 유지된다
- 보조 모니터 독에서 수정을 누르면 그 모니터에 창이 뜨고, 그동안 다른 독을 누를 수 없다
- 모니터를 빼고 다시 꽂아도 독이 돌아오고 설정이 유지된다
- 주 모니터를 바꿔도 독이 모든 모니터에 하나씩만 있다
- 패널 모드에서는 창이 하나만 뜬다
- 런처 보이기로 올린 독이, 다른 창을 누르면 다시 뒤로 내려간다

안정성:
- 탐색기를 다시 시작해도 독과 트레이 아이콘이 돌아온다
- 재부팅을 여러 번 해도 독이 뜨고, 로그에 모니터·소유자 지정 결과가 남는다
- 웹 항목을 연 뒤 다른 창으로 옮겨도 몇 초 뒤 크롬이 앞으로 튀어나오지 않는다
- 판을 끌던 중 Alt+Tab을 눌러도 마우스 오버가 풀린다
